val 指标是 **epoch 级**的。依据当前 Lightning 源码 [fx_validator.py](file:///Users/usst_ziyi/Programs/trae/DeepL/braindecode-lightning/.venv/lib/python3.14/site-packages/lightning/pytorch/trainer/connectors/logger_connector/fx_validator.py#L131-L136)：

| hook | 默认 on_step | 默认 on_epoch |
|---|---|---|
| `training_step` | True | False |
| `validation_step` | False | True |
| `test_step` | False | True |

所以 [module.py](file:///Users/usst_ziyi/Programs/trae/DeepL/braindecode-lightning/exp/models/EEGNet/module.py#L64-71) 中的 `self.log("val_loss", ...)` 和 `self.log_dict(self.val_metrics)` 未显式指定时，均默认 `on_step=False, on_epoch=True` —— 即每个验证集跑完取**所有 step 的平均值**记录一次（`val_loss` / `val_acc` / `val_kappa`），prog_bar 显示的是该 epoch 均值。

对比：`train_loss` 默认是 step 级（每步记一次，无 epoch 聚合）。若想让 val 指标同时记录 step 级曲线，可显式加 `on_step=True`。
